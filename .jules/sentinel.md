## 2026-03-10 - Enforce SSRF Protection and Standard SSL Contexts in Job Preflight Scripts
**Vulnerability:** URL validation and preflight checks in worker scripts (`preflight-check.py`, `batch-preflight.py`, `clean-queue.py`, `validate-queue-urls.py`) used `ssl.CERT_NONE` which disabled TLS verification globally, exposing HTTP clients to MITM attacks. Additionally, untrusted URLs submitted via dashboard `add_job` or CLI scripts lacked DNS IP resolution validation, creating SSRF risks against internal services (e.g. `127.0.0.1`, AWS metadata `169.254.169.254`, private RFC 1918 IPs).
**Learning:** Overriding SSL context parameters (`check_hostname = False`, `verify_mode = ssl.CERT_NONE`) in helper scripts creates widespread TLS bypasses. Furthermore, checking only scheme or string prefixes is insufficient to block SSRF when hostnames resolve to internal or loopback IP addresses.
**Prevention:** Consolidate URL safety validation into a shared `is_safe_url` utility using `socket.getaddrinfo` and `ipaddress` inspection to reject internal ranges, and always use `ssl.create_default_context()` without disabling verification.
